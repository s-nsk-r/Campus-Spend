Question 1(d) Architecture Components & Domain Rationale

1. Peak-Demand Scenario & Hardest API During VIT semester registration and hostel mess advance deadlines, 15,000+ students concurrently access CampusSpend. The hardest-hit API is GET /api/summary/stats due to multi-column relational SQL aggregations (SUM, COUNT, GROUP BY).
2. Edge / Fog Computing Layer (Marked in Amber) Placed at campus hostel network routers and Cloudflare edge PoP. Caches GET /api/summary/stats responses for 10 seconds and verifies JWT tokens locally, intercepting up to 70% of read requests at the network perimeter.
3. Cloud Bursting Component (Marked in Amber) When request queues exceed 100 requests or container CPU exceeds 75%, Nginx bursts overflow traffic to on-demand serverless containers (AWS ECS Fargate). Burst containers scale down to zero once peak traffic subsides.
4. Domain Rationale (Student Finance) Student finance traffic is highly spiky: 95% regular low-volume days, with extreme surges during 2-day fee deadlines. Cloud bursting with Fog caching prevents server crashes during surges without paying for continuous idle compute.
